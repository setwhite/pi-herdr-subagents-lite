# T16 send 端到端（live 子代理）

- [x] 已完成

## 交付物

工具多一个 `send` action。父会话对正在跑的子代理发消息，子代理在同一个 session 里继续。

- schema 改成 spec §3 的 `oneOf`：run 要 `profile` + `task`，send 要 `name` + `message`。
- `run` 在 `agent start` 之前建 `<childSession>.inbox/`。
- 父侧 `send`：名字查不到返回 `unknown_agent` 并列出可用名字；agent 存在就写一条 inbox 消息，返回 `{state:"sent",name}`。
- 子侧：`session_start` 时若 `<sessionFile>.inbox/` 存在，每 `inboxPollMs` 轮询一次。按文件名顺序投递 `sendUserMessage`；忙时带 `deliverAs: "steer"`。投递后移到 `.delivered/`。连续失败 3 次就 `ui.notify(..., "error")` 并停止。`session_shutdown` 停止轮询。
- 新叶子模块 `inbox`，只碰 fs：`createInbox`、`enqueue`、`drain`、`hasInbox`、`removeInbox`。extension 与 subagent 只通过它碰 inbox 文件。
- 文档：`docs/ARCHITECTURE.md` 的模块表、依赖边、seam；`scripts/check-imports.mjs` 的 `EDGES` 与 `node:fs` 名单；`docs/PROMPTS.md` 的工具文案与 inbox 消息文本。

起点：schema 只有 run；没有 inbox。AC1–AC9 红。

## 验收

- AC1：`pnpm exec vitest run -t "accepts run and send"`：schema 根是 `type: "object"` 加 `oneOf`；run 变体的 required 是 `action/profile/task`，send 变体是 `action/name/message`；两个变体都 `additionalProperties: false`。
- AC2：`-t "creates the child inbox before start"`：run 之后 `<childSession>.inbox/` 存在，且 `startAgent` 被调用时它已存在。
- AC3：`-t "queues a message for a live child"`：live 子代理 send 返回 `{"state":"sent","name":"explore-1"}`；inbox 里多一个 `.md`，内容以 `[from parent]` 开头并含消息原文。
- AC4：`-t "rejects unknown agent"`：`isError`，文本以 `unknown_agent:` 开头并列出 `explore-1`；inbox 没有新文件。
- AC5：`-t "delivers inbox messages in order"`：子侧 `isIdle()` 为 true 时两个文件按文件名顺序各投递一次，不带 `deliverAs`；两个文件都进了 `.delivered/`。
- AC6：`-t "steers while the child is busy"`：`isIdle()` 为 false 时 `sendUserMessage` 收到 `{deliverAs:"steer"}`。
- AC7：`-t "does not poll without an inbox"`：没有 inbox 目录时不调 `sendUserMessage`，也不抛错。
- AC8：`-t "stops inbox polling on shutdown"`：`session_shutdown` 之后推进 fake timers，不再调 `sendUserMessage`。
- AC9：`-t "stops inbox polling after three failures"`：投递连续抛错 3 次后 `ui.notify` 只收一次 error，之后不再尝试。
- AC10：`pnpm check` 通过。
