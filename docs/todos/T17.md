## 交付物

子代理退出后，`send` 用同一个 session 把它拉起来。消息照常投递，结果照样回投父会话。

- run 记录在 done 后保留：名字、profile 名、`sessionFile`、`tabId`、`paneId`、pane 标签、`lastHandledSeq`。`active()` 与 `maxConcurrent` 只数 live 的。
- `send` 在 agent 不存在时按顺序检查：session 文件 → 尾部 → profile → pane。任一步失败就返回对应 code，不启动。
- 重启：pane 还在就同 pane `agent start --session <childSession>`；pane 不在就新建 tab（label = 子代理名，cwd 用重新读到的 profile）。不投 brief。`system-prompt` 不是 `task` 时先重写 `<childSession>.identity.md`。
- 重启后重新武装结果投递：`lastHandledSeq` 取 `agent start` 之后 `agent get` 的 `completion_seq`，只投递比它大的。
- herdr 端口加 `hasPane` 与 `resumeAgent`；`docs/ARCHITECTURE.md` 的 herdr 模块说明同步。

起点：done 后记录被删，send 找不到名字。AC1–AC7 红。

## 验收

- AC1：`pnpm exec vitest run -t "resumes the exited child in its pane"`：agent 不在、pane 在、尾部干净时 `resumeAgent` 收到原 `paneId` 与原 `sessionFile`，没有 brief 参数；inbox 文件在 start 之后出现；返回 `{"state":"restarted","name":"explore-1","paneId":<原 paneId>}`。
- AC2：`-t "opens a new tab when the pane is gone"`：`hasPane` 为 false 时新建 tab（label 是 `explore-1`），`resumeAgent` 用新 pane，返回值里的 paneId 是新的。
- AC3：`-t "refuses a dirty session"`：尾部有未完成 toolCall 时返回 `tail_dirty`，不调 `resumeAgent`，不写 inbox。
- AC4：`-t "refuses a missing session"`：session 文件不存在时返回 `session_missing`，不调 `resumeAgent`。
- AC5：`-t "delivers only the result after the restart"`：`completion_seq` 停在基线时不投递；涨过基线后只投递一次，内容是新结果。
- AC6：`-t "re-reads the profile on restart"`：重启前改 profile 的 `model`，`resumeAgent` 的 argv 用新值；删掉 profile 后返回 `unknown_profile`。
- AC7：`-t "keeps finished runs for send"`：一次 run done 并关 tab 后 `send` 仍能找到这个名字；`maxConcurrent` 只数 live，不数保留的记录。
- AC8：`pnpm check` 通过。
