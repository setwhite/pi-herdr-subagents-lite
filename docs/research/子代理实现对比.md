# 子代理实现对比（以 pi-durable 为主）

研究记录；当前契约见 `docs/specs/0001-m0-minimal-subagent.md` 与 `docs/DECISIONS.md`。

调研日期 2026-10-22。基准：仓库 `_repos/earendil-works-pi`，本地 pi 1.4.0、herdr 0.9.5。

## 结论

1. **pi-durable 的子代理不是进程，是 conversation。** 子代理 = 由 task 拥有的子 conversation，在同一 Harness 进程内运行，有自己的 transcript、model、tools、extensions（`packages/durable/README.md:640-680`）。这跟 herdr 版「独立 pi 进程 + pane」是两种世界观。

2. **durable 把前台/后台拆成两种所有权结构，而不是两种投递函数。**
   - 前台：tool task 拥有 child conversation；tool 提交 input 后 `wait()`，settlement 后返回答案（`test/examples/22-subagent-foreground.ts:44-77`）。
   - 后台：parent 里先建一个立即终止的 anchor task，child 挂在 anchor 下；每条消息由一个 reporter task 投递，答案以 `follow-up input` 回到 parent（`test/examples/23-subagent-background.ts:86-131`）。

3. **durable 的可靠性来自「提交先于可见」+ requestId 幂等，不来自 sidecar 文件。**
   崩溃重跑时 `scanConversations({ ownerTaskId })` 找回已有 child（22:52-57）；`requestId: subagent:<taskId>` 让重复提交返回同一次提交（README:643-660）。

4. **abort 语义由所有权决定，不是广播。** abort tool task 会级联到它拥有的 child；background task 是边界，parent 的 Esc / waitForIdle 到边界为止，`abort({ background: true })` 才能穿透（23:62-75、README:672-676）。

5. **它跑不进 pi CLI 扩展。** `packages/coding-agent/src` 里没有任何 durable 引用（`rg 'Harness|durable'` 仅命中两处注释）；本地安装的 pi 包不含 `@earendil-works/pi-durable`；且 `ExtensionContext.modelRegistry` 是 coding-agent 的 `ModelRegistry`（`core/extensions/types.ts:337`），不是 `Harness.open` 需要的 pi-ai `Models`。要在扩展里用它，等于自建 Harness 的模型与存储接线。

6. **子进程方案（herdr / 官方 example）的真正价值只剩两件**：跨进程隔离，以及「人可以在 pane 里接管子代理」。其余能力 durable 用进程内模型都能表达，且更可靠。

## 依据

### durable：前台与后台

| 维度 | 前台（22） | 后台（23） |
|---|---|---|
| 子代理实体 | child conversation，owner = tool task | child conversation，owner = anchor task |
| 完成信号 | `submission.wait()` 的 settlement | reporter task 的 `wait()` |
| 结果去向 | tool 返回值 | 作为 follow-up input 进入 parent |
| 崩溃重跑 | `replay: "safe"` + `scanConversations` | `requestId` 幂等，anchor/reporter 随扩展重新安装后继续 |
| 模型/工具继承 | child 复制 parent 的 agent（model/thinking/cwd/extensions/tools） | 同左，再 `configure` 移除 subagent 扩展、注入 identity |
| 中止 | abort tool → 级联 abort child | `conversation.abort()` 只停当前工作，子代理仍可复用 |
| 状态查询 | 无 | `LiveDoc.run` 判断 working/idle |

### durable：能力边界

- 子代理不能再派子代理：spawn 时 `extensions: { remove: [SubagentTools] }`（23:196-200）。
- steer vs follow-up 由投递参数决定：`whenBusy: "steer" | "followUp"`（23:96-99）。
- name → conversation 映射存在 conversation 级 document，`fork: "initial"`（23:45-58）。
- 每个 reporter 的答案只上报一次：`Subagents.reported` 记录已上报的 EntryId（23:102-120）。

### herdr 子进程方案（对照）

- 启动：生成 wrapper 脚本，`paneStart` 走 plugin argv 入口（`src/launch.ts:296-480`、`src/herdr/client.ts:47-50`）。
- 完成信号：pane 事件 + `.exit`/`.exitcode` sidecar，8 种结果分类（`src/watcher.ts:190-260`）。
- 回传：`pi.sendMessage(msg, { triggerTurn: true, deliverAs: "steer" })`（`index.ts:378,391`）。
- 反问：子进程写 `<session>.ask/`，父侧读；回答写 `.inbox/`，子进程 250ms 轮询（`subagent-done.ts:240,392`）。
- 复杂度来源：进程生命周期 + 人可能接管 pane + 文件系统 IPC。

### 官方 example（对照）

- `pi --mode json -p --no-session`，tool 解析 stdout JSON 流并等到退出（`index.ts:298,344-420,709`）。
- 无 session、无恢复、无 steer、无反问。
- 支持 single / parallel（并发上限 4）/ chain（`{previous}` 占位）。

## 本项目结论

- 目标形态是 pi CLI 扩展 + 常驻子进程 + herdr pane，不是自建 Harness。
- 借 durable 的 requestId 幂等、所有权与 reporter 只上报一次；不搬 daemon 与进程内 conversation。
- pane 保留，因为它是唯一能让人接管子代理的形态。
